# CI and dev-infra conventions

Scope: `.github/workflows/**`, `.husky/**`, `tools/ci/**`, `run.sh`. Source:
root `AGENTS.md` and `.agents/docs/*`.

- `run.sh` is the only installer entrypoint users run via
  `curl -fsSL …/run.sh | sh`. Do not reintroduce `start.sh` or a second
  installer script.
- CE integration tests share one PostgreSQL database and must run serially
  (`--no-file-parallelism`). A change that re-enables file parallelism for
  `test/integration` is a finding.
- CI install and caching follow `tools/ci/install-deps.sh`. Do not add a cache
  step for bun's download cache — it was measured and closed as a net
  regression (#157, #191). A step that caches `~/.bun/install/cache` is a
  finding.
- The pre-push gate's `RUN_CHECKS=y` path runs lint, typecheck and both test
  suites. New work may not be added to it; AI review is opt-in (`[r]` or
  `npm run review`) and advisory.
- A pure-shell helper under `tools/ci/` that other CI logic depends on should
  have a matching `tools/ci/*.test.sh` run from `.github/workflows/_verify.yml`
  before any dependency install, so it cannot be skipped by the docs-only
  filter it may enforce.
