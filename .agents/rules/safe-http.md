For any outbound HTTP in `packages/server/{api,worker,utils}`, use `safeHttp.axios` or `safeHttp.createAxios({ ... })` from `@aiqadam/server-utils`. These wrap `request-filtering-agent` to reject private, loopback, link-local, and cloud-metadata IPs (configurable via `AP_SSRF_ALLOW_LIST`).
Never call raw `fetch(...)` or `axios.create(...)` for URLs sourced from user input, admin config, OAuth token/refresh endpoints, or third-party integrations — they bypass SSRF protection and close the DNS-lookup-to-connect TOCTOU window the filtering agent handles.
For a library that accepts only a `fetch` override and no agent (the AI SDK provider factories are the case this exists for), pass `safeHttp.fetch` — a `fetch`-shaped front end over the same filtered axios instance, so the process keeps exactly one SSRF implementation. Do not reach for undici's `dispatcher` to build a second one. Pass it as a value (`fetch: safeHttp.fetch`), which is what every caller does and which the lint rule never flagged; *calling* `safeHttp.fetch(...)` is still an error everywhere except its own test, exempted by a one-file override in `serverConfigs.utils` (`tools/eslint/server.mjs`) rather than by weakening the shared rule across `api`, `worker` and `utils`. Note `safeHttp.fetch` deliberately drops everything axios attached to a thrown error — an `AxiosError` carries the request config, and the config carries the provider API key, which `loggerRedact`'s static path list cannot cover for `x-api-key`, `api-key`, `x-goog-api-key`, `cf-aig-authorization` or a CUSTOM provider's operator-named header.
For a client that takes neither an axios instance nor a `fetch` override but does take Node `http.Agent`s — the AWS SDK's `requestHandler` is the case this exists for — pass `safeHttp.buildDefaultAgents()` into `new NodeHttpHandler({ ... })`. That is the same `request-filtering-agent` the axios instances wear, reading the same `AP_SSRF_ALLOW_LIST`; use it rather than `safeHttp.buildAgents({ allowList })`, which would make the caller re-parse the allow list and is how the live filter and the configured one drift apart.
**An egress proxy never moves the check off the target.** Through `HTTP(S)_PROXY` the filtering agent's socket goes to the proxy, so it would check the proxy's address, not the target's. The `safeHttp` axios instances therefore run with `proxy: false` (pinned per request by an interceptor too) and take proxying over in `packages/server/utils/src/safe-http-proxy.ts`: a `NO_PROXY` match goes to the filtering agent, and every other target is resolved and checked with `ssrfIpClassifier` against `AP_SSRF_ALLOW_LIST` before a tunnelling agent sends it to the proxy. Never re-enable axios' own proxy handling on these instances; proxying is done by the SSRF-filtered agents only. `buildAgents` / `buildDefaultAgents` always connect directly (a `proxyEnv` option is dropped), which is what keeps the AWS SDK `NodeHttpHandler` behind Bedrock model listing filtered.
**Importing an already-constructed client from another package is a bypass, not an exemption.** `httpClient` from `@aiqadam/qadams-common` is `new AxiosHttpClient()` — no filtering agent, and it sets `NODE_TLS_REJECT_UNAUTHORIZED=0` process-wide. Seven of the nine AI provider strategies imported it and so made unfiltered outbound requests from inside `packages/server/api` while matching none of the raw-`fetch`/`axios` lint patterns (#276). `no-restricted-imports` now names it, and three `no-restricted-syntax` selectors catch the names `httpClient` / `AxiosHttpClient` / `BaseHttpClient` arriving by any other route: `ImportSpecifier` for a deep import or a local re-export, `MemberExpression` for a namespace import or `require(...).httpClient`, and `ObjectPattern > Property` for `const { httpClient } = require(...)` / `= await import(...)`, which binds the name through neither of the other two. All six forms were checked against a probe file; the `ObjectPattern` one exists because the first two let it through.
Hardcoded calls to trusted Qadam Flow endpoints (e.g. `api.aiqadam.org`) must also go through `safeHttp.axios` / `safeHttp.createAxios({ ... })` — there is no separate `apAxios` helper.
This rule is lint-enforced (`no-restricted-syntax` / `no-restricted-imports`) — a raw `fetch(...)`, `globalThis.fetch(...)`, `window.fetch(...)`-style member call, `axios.create(...)`, bare `axios(...)` call, or default `import axios from 'axios'` fails lint. The selectors and import bans live in `tools/eslint/safe-http-rules.mjs` and are applied by `serverConfigs.server` in `tools/eslint/server.mjs`, which the thin `eslint.config.mjs` of `api`, `worker`, `utils` and `shared` compose (ESLint 9 flat config has no cascade, so there is no longer an inherited `packages/server/.eslintrc.json`). `packages/server/utils/src/safe-http.ts` (the wrapper) and the `safeHttp.fetch` call test (`test/safe-http-fetch.test.ts`) are exempted in `serverConfigs.utils`. `packages/server/engine` is out of scope for this rule (it has its own SSRF defence — a global undici dispatcher plus a socket guard in `src/lib/network/ssrf-guard.ts`) and is exempted in `serverConfigs.engine`. `files` globs in a flat config are resolved against the directory of the config file ESLint picked, which is the package's own `eslint.config.mjs` because the `lint` scripts run from the package directory — so a `src/safe-http.ts` pattern means `packages/server/utils/src/safe-http.ts`. After any change to these rules, or to ESLint / typescript-eslint, run `npm run check-safe-http-lint` (CI runs it after lint). It lints `tools/eslint/probes/*.probe` against the real configs and fails if a bypass form is no longer reported on its expected line or a sanctioned exemption stops being exempt; a new bypass form gets a new probe there.
