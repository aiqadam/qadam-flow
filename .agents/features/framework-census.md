# Framework Census

## Summary
The framework-major census of [ADR-0002](../../adr/0002-two-framework-majors-supported-for-at-least-12-months.md) (#803): each instance answers from its own database which steps are pinned to qadam versions built against a framework context version this release no longer runs, so a shim retirement is a visible, repairable list instead of a run-time surprise. It never blocks a start-up and never disables a flow (#435). Everything is resolved offline: bundled qadams from the image, custom qadams from `qadam_metadata.contextVersion` (#802).

## Key Files
- `packages/qadams/framework/src/lib/context/framework-support-table.json` — the ADR-0002 support table (#801); one row per framework major. The last row's major is the framework this tree builds.
- `packages/qadams/framework/src/lib/context/framework-support.ts` — typed access to the table, `ENGINE_CONTEXT_VERSIONS` (the context versions the dispatcher in `versioning.ts` still handles) and `PREDATES_CONTEXT_INFO` (`'none'`).
- `packages/server/api/src/app/qadams/census/framework-census-policy.ts` — the ADR-0002 rules in one place: what this release runs, what an official qadam's framework major means, what an unknown context version counts as, and which context versions are retired. Every reader goes through `engineContextVersions()`, so a test can stand in for a release that retired a shim.
- `packages/server/api/src/app/qadams/census/framework-census-service.ts` — the query: stored flow versions → pinned `name@version` → context version → status (`current` / `legacy` / `unsupported`). It never writes and selects only the columns it needs, and pins resolve through `qadamMetadataService.resolveVersion` (the registry's named columns), so it reads a database whose tables predate this release's columns. A missing `contextVersion` column reads as unknown; any other read error is thrown, never reported as an unsupported step. It walks a platform one flow batch (100 flows) at a time and counts statuses as it goes, resolving each distinct pin once (in batches of 20); it keeps only the `legacy` and `unsupported` steps, or at most `maxSteps` of them, `unsupported` first. Flow versions whose step tree cannot be walked are counted as `unreadableVersions`, per platform and for the instance.
- `packages/server/api/src/app/qadams/census/framework-build-major.ts` — the framework major of a bundled official build, from its own `package.json` (`workspace:*` = this tree's major; a version or range by its lowest version). Official qadams the image bundles have no `qadam_metadata` row.
- `packages/server/api/src/app/qadams/census/framework-census-marking.ts` — the per-request half: `unsupportedPins()` for the MCP surfaces, `logRetirement()` for the boot log line. It skips all resolution while no shim has been retired.
- `packages/server/api/src/app/qadams/census/framework-census-controller.ts` / `framework-census-module.ts` — `GET /v1/framework-census`, platform admin only, scoped to the caller's platform.
- `packages/server/api/src/app/qadams/census/framework-census-cache.ts` — the endpoint's per-platform cache: one census walk per platform per API process per 5 minutes, shared by concurrent requests (single-flight); a failure is not cached. Keyed by platform and the retired set (#838).
- `packages/server/api/src/scripts/framework-census-doctor.ts` — the `doctor` command (`npm run doctor`): run from the new image before switching containers, it lists the steps the release will stop running. What it prints and its exit code are `framework-census-doctor-report.ts`.
- `packages/server/api/src/app/database/database-connection.ts` — `openReadOnlyDatabaseConnection()`, the doctor's connection: unlike the application's (`migrationsRun: true`), it never migrates on `initialize()`, installs no extension, and sets `default_transaction_read_only`, so Postgres refuses any write on it. That startup option can be lost (a `POSTGRES_URL` with its own `?options=`, PgBouncer's `ignore_startup_parameters`), so after connecting it runs `SHOW default_transaction_read_only` and fails closed unless the session reports `on` (#838).
- `packages/server/api/src/app/qadams/qadam-context-version-backfill.ts` — fills `qadam_metadata.contextVersion` for rows that predate it (#802).
- `packages/server/api/src/app/mcp/tools/ap-flow-structure.ts` / `ap-validate-flow.ts` — the MCP marking: a step whose pin needs a retired context version carries `frameworkVersionSupported: false` / the `framework_version` issue category.
- `packages/web/src/app/routes/platform/infra/health/components/framework-census-banner.tsx` — the operator banner on the platform health page.

## Domain Terms
- **Framework major** — a major of `@aiqadam/qadams-framework`; since 1.0.0 a new engine ↔ qadam `context` version is a new major (ADR-0002).
- **Context version** — what a qadam reports through `getContextInfo()`: `'1'` / `'2'` (a `ContextVersion`), `'none'` (it predates `getContextInfo`), or unknown.
- **Support table** — `framework-support-table.json`: per major, its context versions and release dates. A major is supported while it is the current or the previous one and for at least 12 months after its successor.
- **Retired context version** — a context version the support table lists that `ENGINE_CONTEXT_VERSIONS` no longer contains; a step needing one stops running on this release.
- **Legacy** — runs through a context shim today (context V1 or `none`), so it stops running when that shim is retired.
- **Unsupported** — this release no longer runs the step's context version. An unknown context version counts as still needing the old contract, so it is `legacy` before the first retirement and `unsupported` after it.

## Resolution
A step is counted once per meaningful version of its flow: the published version (what runs) and the latest version (what the builder edits and test runs use), deduped when they are the same. Each distinct pin is resolved once:
- **Official** (`@aiqadam/...`, or a name the image bundles): the version `qadamMetadataService.get` resolves the pin to; a bundled build's framework major comes from its own `dist/package.json` (`workspace:*` = this tree's major), a persisted row's from `qadam_metadata.contextVersion`. Before `qadams-framework@1.0.0` every official qadam reports context V2.
- **Custom**: the version the pin resolves to, then that row's `qadam_metadata.contextVersion` (`1` / `2` / `NONE` / `UNRECOGNISED`; `NULL` is unknown).
- **Unresolvable**: no qadam version on this instance answers the pin — unknown, which counts as still needing the old contract. An official pin that resolves to a version with neither a bundled build nor a persisted official row is not unresolvable: it stays `official`, with an unknown context version (until #779 reads the local store). The MCP marking leaves these to the `qadam_version` signal (one error with the right remedy, not two); the census and the doctor count them.

## Surfaces
- **`doctor`** (`npm run doctor`, or `docker compose run --rm --entrypoint node app packages/server/api/dist/src/scripts/framework-census-doctor.js`) lists the steps that will stop running and how many flow versions it could not read; `--fail-on-findings` exits 1 when a step stops running or a flow version could not be read (an unknown counts as still needing the old contract, so the doctor never calls such an instance all-clear). It reads the database through `openReadOnlyDatabaseConnection()`, so a database the new image has not migrated stays unmigrated. A database error exits 1 with the error. The release itself never blocks.
- **`GET /v1/framework-census`** returns the platform's census for the Health page banner. While nothing is retired it walks no flows and answers `ran: false` with an empty summary and step list (no step can be unsupported then; the doctor lists what a coming release would stop running). Once a context version is retired it returns the summary, `totalSteps`, and at most 200 steps, unsupported first, from the per-platform cache (up to 5 minutes stale).
- **MCP**: `ap_flow_structure` marks an affected step `⚠️ FRAMEWORK VERSION NO LONGER SUPPORTED: update this step` and carries `frameworkVersionSupported: false`; `ap_validate_flow` reports the `framework_version` category. A pin that does not resolve gets neither — it already carries the `qadam_version` error / "pinned version unavailable" mark.
- **Boot log**: one warning line when the release has retired a context version.
- **Not built yet**: per-step marking in the web builder and in a run's step list (ADR-0002 names both); today a person sees the Health page banner, an agent sees the MCP marks.
