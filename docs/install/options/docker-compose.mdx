The Docker Compose stack is the recommended way to run Qadam Flow: separate app and worker containers backed by PostgreSQL and Redis.

## Quick install (recommended)

The one-line installer sets this stack up for you — it downloads `docker-compose.yml`, generates a `.env` with random secrets, pulls `ghcr.io/aiqadam/qadam-flow:latest`, and brings everything up:

```bash
curl -fsSL https://flow.aiqadam.org/run.sh | sh
```

Then open [http://localhost:8080/sign-up](http://localhost:8080/sign-up). The first account to sign up owns the platform.

See [Docker](./docker) for the full breakdown of what the installer does and the variables it accepts (`QADAM_FLOW_DIR`, `QADAM_FLOW_IMAGE`, `QADAM_FLOW_REF`, `QADAM_FLOW_PORT`).

## Manual setup

Use this if you want the stack under version control, or you intend to modify `docker-compose.yml`.

### Prerequisites

- [Git](https://git-scm.com/book/en/v2/Getting-Started-Installing-Git)
- [Docker](https://docs.docker.com/get-docker/) with Compose v2

<Warning>
`docker-compose` (with a hyphen) is Compose v1 and will not work. Install [Compose v2](https://docs.docker.com/compose/install/) and use `docker compose` (with a space).
</Warning>

<Steps>
  <Step title="Clone the repository">
    ```bash
    git clone https://github.com/aiqadam/qadam-flow.git
    cd qadam-flow
    ```

    If you only want to run the stack and not build from source, download just the compose file instead:

    ```bash
    mkdir qadam-flow && cd qadam-flow
    curl -fsSL https://raw.githubusercontent.com/aiqadam/qadam-flow/main/docker-compose.yml -o docker-compose.yml
    ```
  </Step>
  <Step title="Create a .env file">
    `docker-compose.yml` reads every service's configuration from `.env` in the same directory, so this file is required. Generate the secrets first:

    ```bash
    openssl rand -hex 16   # AP_ENCRYPTION_KEY  (must be 32 hex characters)
    openssl rand -hex 32   # AP_JWT_SECRET
    openssl rand -hex 12   # AP_POSTGRES_PASSWORD
    ```

    Then write `.env`:

    ```dotenv
    QADAM_FLOW_IMAGE=ghcr.io/aiqadam/qadam-flow:latest

    AP_ENVIRONMENT=prod
    AP_FRONTEND_URL=http://localhost:8080

    # Database
    AP_DB_TYPE=POSTGRES
    AP_POSTGRES_HOST=postgres
    AP_POSTGRES_PORT=5432
    AP_POSTGRES_DATABASE=qadam_flow
    AP_POSTGRES_USERNAME=postgres
    AP_POSTGRES_PASSWORD=replace-with-openssl-rand-hex-12
    AP_POSTGRES_USE_SSL=false

    # Queue
    AP_REDIS_TYPE=STANDALONE
    AP_REDIS_HOST=redis
    AP_REDIS_PORT=6379

    # Secrets
    AP_ENCRYPTION_KEY=replace-with-openssl-rand-hex-16
    AP_JWT_SECRET=replace-with-openssl-rand-hex-32

    # Optional
    AP_TELEMETRY_ENABLED=false
    AP_EXECUTION_MODE=UNSANDBOXED
    AP_WEBHOOK_TIMEOUT_SECONDS=30
    AP_TRIGGER_DEFAULT_POLL_INTERVAL=5
    ```

    <Note>
    `AP_ENVIRONMENT` is lowercase: `prod`, `dev`, or `test`. Any other value makes the server throw on startup.
    </Note>

    The full list of settings lives in [Environment Variables](../configuration/environment-variables).
  </Step>
  <Step title="Start the stack">
    ```bash
    docker compose pull
    docker compose up -d
    ```

    Compose starts four services: `app` (published on `8080:80`), five `worker` replicas, `postgres` (`pgvector/pgvector:0.8.0-pg14`), and `redis` (`redis:7.0.7`). PostgreSQL and Redis data live in the named volumes `postgres_data` and `redis_data`.
  </Step>
  <Step title="Sign up">
    Open [http://localhost:8080/sign-up](http://localhost:8080/sign-up) — the first account owns the platform.

    Watch the logs while it boots:

    ```bash
    docker compose logs -f app worker
    ```
  </Step>
</Steps>

<Warning>
Before exposing this to the internet, change the PostgreSQL credentials from any example values, put a reverse proxy with TLS in front of it (see [Setup SSL](../guides/setup-ssl)), and re-read the [configuration guide](../configuration/environment-variables).
</Warning>

## Configure the webhook URL

`AP_FRONTEND_URL` is used to build webhook and redirect URLs, so it has to be reachable from the internet for app triggers to fire. For local testing, expose port `8080` with [ngrok](https://ngrok.com/) and set `AP_FRONTEND_URL` to the HTTPS URL it prints, then run `docker compose up -d`. Full walkthrough on the [Docker](./docker#configure-the-webhook-url) page.

## Upgrade

<Warning>
Review the [breaking changes](../configuration/breaking-changes) for your target version first.
</Warning>

<Steps>
  <Step title="Refresh the compose file">
    If you cloned the repository:

    ```bash
    git pull
    ```

    If you only downloaded `docker-compose.yml`, download it again:

    ```bash
    curl -fsSL https://raw.githubusercontent.com/aiqadam/qadam-flow/main/docker-compose.yml -o docker-compose.yml
    ```
  </Step>
  <Step title="Pull the new image">
    ```bash
    docker compose pull
    ```
  </Step>
  <Step title="Restart">
    ```bash
    docker compose up -d --remove-orphans
    ```

    Migrations run automatically on boot. Your `.env` and volumes are untouched.
  </Step>
</Steps>

To pin a specific version instead of tracking `latest`, set `QADAM_FLOW_IMAGE=ghcr.io/aiqadam/qadam-flow:<version>` in `.env`. See [Rollback](../guides/rollback) for going back to an earlier version.

## Stop and delete

Stop the stack but keep all data:

```bash
docker compose down
```

<Warning>
The next command removes the containers **and** the `postgres_data` and `redis_data` volumes. Every flow, run, and connection is deleted permanently.
</Warning>

```bash
docker compose down -v
```
