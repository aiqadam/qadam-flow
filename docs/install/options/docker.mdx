The one-line installer sets up the full stack — app, workers, PostgreSQL and Redis — with generated secrets. It is the supported way to run Qadam Flow with Docker.

<Note>
**The all-in-one container has been removed.** Earlier images accepted `AP_CONTAINER_TYPE=WORKER_AND_APP` (also the default when the variable was unset) and ran the API and a worker side by side in one container, supervised by PM2 inside the image. That supervisor hid crashes from `docker ps`, and the mode shipped without a working worker — so the container answered HTTP while no flow ever executed. The API and the worker now run as separate containers, each supervised by Docker, and the entrypoint refuses to start rather than guess. See [Breaking Changes](../configuration/breaking-changes).
</Note>

## Quick install (recommended)

Paste this into any macOS, Linux, or WSL2 shell:

```bash
curl -fsSL https://flow.aiqadam.org/run.sh | sh
```

When it finishes, open [http://localhost:8080/sign-up](http://localhost:8080/sign-up). The first account to sign up owns the platform.

### What the installer does

<Steps>
  <Step title="Checks your machine">
    Requires `curl`, `openssl`, `docker`, and Docker Compose v2 (`docker compose`), and verifies the Docker daemon is reachable. Native Windows shells are refused — run it from WSL2.
  </Step>
  <Step title="Creates an install directory">
    Everything lands in `./qadam-flow` in your current directory. Re-running the installer in the same place refreshes the compose file and keeps your existing `.env`.
  </Step>
  <Step title="Downloads docker-compose.yml">
    Fetched from `https://raw.githubusercontent.com/aiqadam/qadam-flow/main/docker-compose.yml`. No git clone and no source build.
  </Step>
  <Step title="Generates a .env with fresh secrets">
    `AP_ENCRYPTION_KEY`, `AP_JWT_SECRET` and the PostgreSQL password are generated with `openssl rand`. Delete `.env` and re-run to rotate them.
  </Step>
  <Step title="Pulls the image and starts the stack">
    Runs `docker compose pull` followed by `docker compose up -d`, using `ghcr.io/aiqadam/qadam-flow:latest` (roughly 400 MB on first pull).
  </Step>
  <Step title="Waits for the API">
    Polls `http://localhost:8080/api/v1/flags` for up to 3 minutes, then prints the URL.
  </Step>
</Steps>

### Installer options

Set these before piping to `sh`, for example `QADAM_FLOW_DIR=/opt/qadam-flow`:

| Variable           | Default                             | Effect                                                             |
| ------------------ | ----------------------------------- | ------------------------------------------------------------------ |
| `QADAM_FLOW_DIR`   | `qadam-flow`                        | Install directory the compose file and `.env` are written to.       |
| `QADAM_FLOW_IMAGE` | `ghcr.io/aiqadam/qadam-flow:latest` | Image used by the app and worker services.                         |
| `QADAM_FLOW_REF`   | `main`                              | Git ref the `docker-compose.yml` is downloaded from.                |
| `QADAM_FLOW_PORT`  | `8080`                              | Host port the app is published on, and the port used for `AP_FRONTEND_URL` and the health check. |

<Note>
`QADAM_FLOW_PORT` is written into the generated `.env`, and `docker-compose.yml` interpolates it into the app's port mapping (`${QADAM_FLOW_PORT:-8080}:80`). Re-running the installer against an existing install adopts the port already recorded in that `.env` unless you set `QADAM_FLOW_PORT` again, in which case the `.env` is updated in place.
</Note>

<Warning>
**Upgrading from an install that changed the port by hand.** Earlier versions ignored `QADAM_FLOW_PORT`, so the only way to move the port was to edit the `8080:80` mapping in `qadam-flow/docker-compose.yml` — and the installer overwrites that file on every run, silently putting you back on 8080. Move the port into `.env` instead: re-run with `QADAM_FLOW_PORT=<your port>`, which records it in `.env` and repoints `AP_FRONTEND_URL`. The installer warns if it spots an `AP_FRONTEND_URL` pointing at a port the stack will not publish.
</Warning>

### Memory budget

Give the `app` service at least **768 MB**. Node sizes its V8 heap to the memory the
container is allowed, and at a `mem_limit` around `400m` the very first sign-up can
exhaust the heap on small hosts (Raspberry Pi, 1–2 GB VPS). If you need to run tighter
than that, set `NODE_OPTIONS=--max-old-space-size=<MB>` in `.env` to a value comfortably
below the limit rather than letting V8 auto-tune into it.

A process that runs out of heap now exits the container, so Docker's `restart:` policy
restarts it and the crash shows up in `docker ps` (a rising restart count) and
`docker events`. Earlier images supervised Node with PM2 inside the container, which
restarted the process in place and left the container reporting `Up` while sign-up hung.

### Day-two commands

Run these from your install directory (`qadam-flow` by default):

```bash
docker compose logs -f app worker             # follow logs
docker compose down                           # stop, keep data
docker compose pull && docker compose up -d   # upgrade to the latest image
docker compose down -v                        # stop AND delete all data
```

For the details of the compose stack and every value in `.env`, see [Docker Compose](./docker-compose).

## Configure the webhook URL

By default Qadam Flow uses `AP_FRONTEND_URL` to build webhook URLs. If you are self-hosting on a personal machine, that URL has to be reachable from the internet for app triggers to work.

The quickest way to expose a local port is [ngrok](https://ngrok.com/). It is not suitable for production.

<Steps>
  <Step title="Install ngrok">
    Follow the [ngrok getting started guide](https://ngrok.com/docs/getting-started/).
  </Step>
  <Step title="Expose port 8080">
    ```bash
    ngrok http 8080
    ```
  </Step>
  <Step title="Point Qadam Flow at the tunnel">
    Set `AP_FRONTEND_URL` in `.env` and run `docker compose up -d`.
  </Step>
</Steps>

## Upgrade

<Info>
Review the [breaking changes](../configuration/breaking-changes) before upgrading, and back up your data first.
</Info>

### One-line installer

From your install directory:

```bash
cd qadam-flow
docker compose pull
docker compose up -d --remove-orphans
```

Your `.env` and the PostgreSQL and Redis volumes are untouched.

### Coming from the all-in-one container

<Warning>
**Do not pull a newer image over an all-in-one install.** The current image refuses to start without `AP_CONTAINER_TYPE=APP` or `WORKER`, so the container will exit instead of upgrading in place.

There is **no automated migration** from the embedded PGLite database to PostgreSQL. Your flows, connections and runs live in `~/.qadam-flow` and there is no export tool that moves them into a compose install. Until one exists, either stay on the image tag you are running now, or rebuild your flows in a fresh install.
</Warning>

Back up the directory before doing anything else:

```bash
docker stop qadam-flow
cp -r ~/.qadam-flow ~/.qadam-flow-backup
```

## Uninstall

<Warning>
Both commands below delete your flows, runs, and connections. There is no undo.
</Warning>

For the compose stack:

```bash
cd qadam-flow
docker compose down -v
```

For an older all-in-one container:

```bash
docker rm -f qadam-flow
rm -rf ~/.qadam-flow
```
