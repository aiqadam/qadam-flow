Narrow the qadam-facing `@aiqadam/shared` re-export surface before `1.0.0` (#959): remove 28 single-qadam DTOs that their owner only ever consumed as types — tables request/record types (`CreateRecordsRequest`, `Table`, `ListTablesRequest`, …), agent/MCP types (`AgentKnowledgeBaseTool`, `AgentMcpTool`, `McpTrigger`, `ExecuteToolResponse`, …) and AI-provider config types (`AIProviderModel`, `AzureProviderConfig`, …); see `packages/qadams/framework/src/lib/shared-reexports.ts`. These were a semver promise to external qadam authors for symbols nobody outside their own defining qadam needs. Note that several removed names are Zod schemas or enums in `@aiqadam/shared`, so this also removes value exports (for example `Table.parse` or the `UpsertAction` enum); that removal is the intended narrowing. Seven other single-qadam DTOs stay exported — `Field`, `Filter`, `PopulatedRecord` (tables) and `AgentResult`, `AgentTool`, `AgentOutputField`, `AgentFlowTool` (ai) — because they appear in those qadams' published `.d.ts`, where a type import still names `@aiqadam/shared`, and the publish gate rejects that. The remaining single-qadam runtime values (enums, functions, constants — e.g. `FieldType`, `AIProviderName`, the subflow headers) are unaffected and stay exported, because `@aiqadam/shared` is private/unpublished and cannot be a real runtime dependency of a standalone-published qadam.
