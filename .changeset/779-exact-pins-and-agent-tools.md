A step or an agent tool pinned to a qadam version this instance does not have no longer silently runs a different build (ADR-0003, #779). The engine runs the pin from the qadam version store or from the image's build of that same version; for a release pin that neither holds, it runs the image's build only inside the pin's caret range (never another major, on `0.x` never another minor, never an older build) and logs `The pinned version is not available, running the image's build inside the pin's caret range instead`; otherwise the run fails with the pin named. A snapshot pin (`x.y.z-main.<n>`) is exact: no other build stands in for it and it is never installed from a registry. The worker also checks the qadams that an agent step uses as tools before the run, as it does for steps, so a custom qadam used only as an agent tool is installed and an unavailable one (or a tool whose version is no version) fails the flow with its pin named; `ap_validate_flow` and `ap_flow_structure` now report tool pins. Flows that only ran through the old fallback or a stale worker-cache answer now fail and need a re-pin: see "Unreleased" in docs/install/configuration/breaking-changes.mdx. The worker's cache moves to `cache/v13`: its first jobs after the upgrade look every pin up again and reinstall custom qadams, and the old `cache/v12` is removed once idle.
