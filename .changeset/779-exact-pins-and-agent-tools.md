A step that pins an official qadam version no longer silently runs a different build (ADR-0003, #779). The engine runs the pin from the qadam version store or from the image's build of that same version; for a release pin that neither holds, it runs the image's build only inside the pin's caret range (never another major, on `0.x` never another minor, never an older build) and logs `The pinned version is not available, running the image's build inside the pin's caret range instead`; otherwise the run fails with the pin named. A flow whose pin was out of range and kept working through a worker's cached lookup now fails; update its step to a version the instance has. A snapshot pin (`x.y.z-main.<n>`) is exact: no other build stands in for it and it is never installed from a registry. The worker also checks the qadams that an agent step uses as tools before the run, as it does for steps, so a custom qadam used only as an agent tool is installed and an unavailable one fails the run with its pin named. The worker's cache moves to `cache/v13`: its first jobs after the upgrade look every pin up again and reinstall custom qadams, and the old `cache/v12` is removed once idle.
